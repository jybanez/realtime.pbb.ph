# Transport observer review artifact

Separate preparation from PR3 callback stages. Default REALTIME_TRANSPORT_OBSERVER_ENABLED=false installs no wrapper or UDP sink. When explicitly enabled, the app-owned Ratchet subclass wraps IoServer's application before HttpServer. No vendor source changes. Callbacks forward once, preserve product exceptions, and observer failures are isolated. A second forwarding wrapper records post-upgrade entry before existing gateway onOpen. Exact UUID mapping travels through Ratchet connection decorators via a dedicated connection property. Existing authentication and product ACK behavior are unchanged.

Post-upgrade records include gateway_connection_id equal to the exact decorated connection's spl_object_hash, matching the existing gateway stage connection_id within the same PID. This bridges the transport-generated connection ID and attempt UUID to callback diagnostics without matching by timestamp proximity. Object hashes can be reused after object destruction, so scope the mapping to this connection lifetime and its transport ID, not a process-wide permanent identity.

Loop-delivered accept is not OS accept. First-data timestamp is event-loop delivery before HTTP parsing, not network packet arrival. Post-upgrade timestamp is after WsServer's handshake send call, not client receipt or flush. UTC is for cross-layer comparison with clock uncertainty; monotonic deltas apply only within this process. No HTTP text, frame, token, payload, SQL, header or remote address is emitted. Only lowercase canonical UUID diag_attempt is extracted; absence/invalid input yields null. UUID must be newly generated per explicit attempt; it grants no authorization.

Records are lossy nonblocking UDP to127.0.0.1 only, configurable destination port(default9997). There is no receiver callback, blocking connect, disk write, retry or delivery ACK in the gateway. No collector is started by the feature. Receiver stall/absence may drop data; a successful send means kernel submission only. Counters indicate attempted datagrams and locally detected errors, not confirmed receipt or undetectable kernel drops. Missing sockets extension disables delivery without changing service.

Caps per process activation: five-minute emission/connection enrollment window,256 enrolled concurrent connections,4096 attempted datagrams,1024 bytes/datagram and1MiB attempted aggregate bytes. At cap, observer drops records or enrollment only; service continues. State clears on close/error/product exception. Already enrolled connections retain bounded state until cleanup even after emission expiry. Re-enabling requires a separately approved startup, not an automatic restart. No state grows with message volume: first-data records only once. Close may occur at both wrappers, with idempotent cleanup.

Tests exercise a real HttpServer/WsServer handshake with a token-bearing request and exact UUID through decorators, callback exception cleanup/forwarding,256 cap and stalled receiving socket with no reads. Benchmarks use5x1000 synthetic connections with a stalled local UDP receiver and compare enabled/off. They measure observer mechanics, not production gateway/OS/network overhead; caps, host load and OS UDP behavior affect numbers. Standard nonblocking kernel API behavior is the protection against sink waiting; timing checks are corroborating local evidence, not a universal maximum latency guarantee.

Final synthetic measurements on this shared Windows/PHP 8.2.29 host: off median 0.153297 ms/connection (range 0.132796–0.223474); enabled with stalled UDP receiver median 2.303977 ms (range 2.002878–2.615888). Median difference 2.150680 ms is a synthetic comparison, not a production per-open bound. Five focused tests / 27 assertions pass using an explicit bootstrap that verifies this checkout's App class paths. UTC formatting now uses one wall-clock sample for seconds and milliseconds. The 6,000-connection stalled-receiver test uses a 15-second aggregate watchdog, not a service latency timeout. An initial five-second watchdog failed at 7.690 seconds, so no claim is made that all 6,000 complete within five seconds. No product timeout was changed.

## Apache proposal, separate operational scope

apache-realtime-transport-logging.conf.proposed is a reviewable additive snippet for the two realtime vhosts only; existing proxy/auth directives remain. No live config was edited. Selective UUID environment extraction and path-only log format follow Apache2.4 documentation: https://httpd.apache.org/docs/2.4/mod/mod_setenvif.html and https://httpd.apache.org/docs/2.4/mod/mod_log_config.html. Must syntax-check an isolated config and verify token omission and UUID extraction before approval. Duplicate UUID fields are ambiguous input and must not be used for exact correlation. Current gateway extraction and Apache expression are intended for a uniquely generated single field only.

Apache config does not dynamically reload itself. Applying later requires the approved Windows WAMP Apache service's reload/restart workflow (verify actual service identity first), affecting all apps in that process; long WebSocket connections may close or finish under the prior generation. Syntax check alone does not load config. The final snippet passed httpd.exe -t with a post-config -c Include; this verifies parsing/module availability only, not selective extraction or tunnel log semantics. An initial pre-config -C Include failed because SRVROOT was not yet defined; no live config was changed. Scope a bounded capture and log rotation/retention before applying. Rollback removes the snippet from both vhosts and requires the same approved reload workflow; preserve sanitized log evidence first. Log rows may emit only when the tunnel ends, and elapsed time may be tunnel lifetime, not upgrade duration. Verify these semantics before a human call. OS backlog allocation may still require a separately reviewed bounded TCPETW plan; no ETW activation is included.

Read-only service lookup identifies wampapache64 as Running. Approval must still specify its actual WAMP/Windows reload/restart procedure and idle impact; this source preparation did not execute that workflow.
