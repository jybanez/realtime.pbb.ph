# Nonwaiting callback emission proposal

Prepared implementation for review only; not deployed or accepted. PR3 now routes detailed callback/request diagnostic records through RealtimeDiagnosticEmitter, replacing their synchronous logging. The prior synthetic numbers do not establish a low-load baseline. Hotline's 7920 serialized tiny PHP8.2.29 sample measured aggregate median 0.129733ms and nine disk logs 18.075ms, with variable ranges and no contemporaneous host samples. Historical worker exit/stderr/marker timing was lost during fixture cleanup. Its cause and the benchmark discrepancy remain unknown.

## Proposed gateway boundary

Keep callback SQL/span aggregation in memory. Route detailed callback records to an explicit diagnostic emitter rather than Monolog/file handlers. Do not change product logging, authorization, forwarding, ACK order, or exception propagation. Tracing remains default off. Transport PR4 and callback PR3 remain separate review targets until an explicitly reviewed integration preserves both.

Use a literal loopback nonblocking UDP socket, created once at startup, with no DNS, disk, retries, send acknowledgments, receiver callback or synchronous fallback. Drop on missing socket, encoding failure, oversized record, exhausted budget or send failure. A collector running in a separate process owns any file I/O; its stalled or absent receiver must never induce producer retry. UDP delivery is lossy; send success is not collector receipt. Existing slow-callback warnings are outside this detailed emitter and need separate cost review before capture acceptance.

Proposed hard volume caps per gateway capture: five minutes from emitter creation, 4096 attempted records, 4 MiB eligible attempted-send bytes, and 2048 bytes per record. Consume one record attempt before encoding; consume bytes only for encoded records at most2048 bytes that fit the remaining byte budget, before socket availability/send. Encoding failures, oversized records and remaining-byte-budget rejection consume an attempt but no bytes; unavailable or failed sends consume both. No reset on failure, no periodic flush, no gateway queue and no shutdown drain. Check expiry and record exhaustion before encoding. Limit accepted fields, UTF-8 metadata and fixed SQL operation maps before serialization so discarded inputs cannot create unbounded encoding work. Reject oversized records whole, rather than truncate JSON or enqueue partial records. Keep only fixed counters (attempted, sent, dropped and reason counts); expose them through a separately reviewed bounded path without per-drop logging. These caps bound work volume, not OS scheduling time or guaranteed callback latency.

Records retain PID, process-local span/parent IDs, gateway connection identity scoped to its object lifetime, request ID and existing sanitized stage/SQL aggregates. Preserve PR3's signal enum and payload/token/SQL-text exclusion. Do not infer browser receipt, OS accept or arrival from emitter timestamps. Child emission cost remains outside the child's measured duration and inside the parent's unaccounted interval; document this observer effect.

## Collector preparation and residual warning review

It binds only literal loopback, creates a new output file without overwriting evidence, and accepts duration1..300 seconds. Sender attempt sequence is retained, but absent/reordered sequences are not allocated to kernel loss or confirmed delivery. A filesystem call can stall this independent collector: its time/volume checks do not bound disk syscall latency. No live collector launch or receipt proof is claimed. Loopback is not an authentication boundary; another local process can forge schema-valid metadata. The whitelist is a payload-exclusion check, not a guarantee that client-controlled request IDs never contain sensitive text.
