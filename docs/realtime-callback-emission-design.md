# Nonwaiting callback emission proposal

Prepared implementation for review only; not deployed or accepted. PR3 now routes detailed callback/request diagnostic records through RealtimeDiagnosticEmitter, replacing their synchronous logging. The prior synthetic numbers do not establish a low-load baseline. Hotline's 7920 serialized tiny PHP8.2.29 sample measured aggregate median 0.129733ms and nine disk logs 18.075ms, with variable ranges and no contemporaneous host samples. Historical worker exit/stderr/marker timing was lost during fixture cleanup. Its cause and the benchmark discrepancy remain unknown.

## Proposed gateway boundary

Keep callback SQL/span aggregation in memory. Route detailed callback records to an explicit diagnostic emitter rather than Monolog/file handlers. Do not change product logging, authorization, forwarding, ACK order, or exception propagation. Tracing remains default off. Transport PR4 and callback PR3 remain separate review targets until an explicitly reviewed integration preserves both.

Use a literal loopback nonblocking UDP socket, created once at startup, with no DNS, disk, retries, send acknowledgments, receiver callback or synchronous fallback. Drop on missing socket, encoding failure, oversized record, exhausted budget or send failure. A collector running in a separate process owns any file I/O; its stalled or absent receiver must never induce producer retry. UDP delivery is lossy; send success is not collector receipt. Existing slow-callback warnings are outside this detailed emitter and need separate cost review before capture acceptance.

Proposed hard volume caps per gateway capture: five minutes from emitter creation, 4096 attempted records, 4 MiB attempted encoded bytes, and 2048 bytes per record. Consume attempted record/byte budgets before send; no reset on failure, no periodic flush, no gateway queue and no shutdown drain. Check expiry and record exhaustion before encoding. Limit accepted fields, UTF-8 metadata and fixed SQL operation maps before serialization so discarded inputs cannot create unbounded encoding work. Reject oversized records whole, rather than truncate JSON or enqueue partial records. Keep only fixed counters (attempted, sent, dropped and reason counts); expose them through a separately reviewed bounded path without per-drop logging. These caps bound work volume, not OS scheduling time or guaranteed callback latency.

Records retain PID, process-local span/parent IDs, gateway connection identity scoped to its object lifetime, request ID and existing sanitized stage/SQL aggregates. Preserve PR3's signal enum and payload/token/SQL-text exclusion. Do not infer browser receipt, OS accept or arrival from emitter timestamps. Child emission cost remains outside the child's measured duration and inside the parent's unaccounted interval; document this observer effect.

## Review and bounded validation gates

First review the emitter implementation and exact clean dependency/source mapping. Under one-owner serialized execution, use a small offline fixture with a never-reading receiver and an absent receiver to check drop budgets, expiry, exception isolation and bounded state. Preserve raw output and source/runtime mapping; avoid full suites and large benchmarks on the slow shared host. Test product callbacks forward once and propagate the same exception even when diagnostic sending fails. Independently verify real gateway upgrade/auth/signaling/duplicate-response behavior with clean dependencies before claiming compatibility. Review the collector separately, including receiver binding and privacy; no automatic collector launch is authorized.

Change the worker fixture to report distinct PHP entry, autoload completion, kernel bootstrap completion, fake HTTP entry and sending-marker timestamps. Preserve bounded stderr, child exit and artifacts on failure. Treat readiness timeout as a fixture startup failure and report gateway responsiveness as unexercised. Start measuring gateway work only after confirmed worker readiness; use a bounded startup deadline and explicit termination/cleanup, not a production timeout increase. Never classify a forced termination exit as a source exception. This evidence is still outstanding.

The implementation defaults to UDP port9998, separate from PR4 transport port9997. It only creates a socket when gateway timing is enabled at construction. Stats are available in memory; no per-drop logger, timer or collector is added. Fixed record schema excludes arbitrary context and SQL operation keys. Record/encoding failures consume an attempt; oversized records consume no send bytes. Socket send success is not delivery. Existing product logs and timing-off slow-callback warning disk paths remain unchanged and require cost consideration.

Prepared worker harness keeps the existing five-second startup deadline, retains startup stage timestamps/stdout/stderr/result status on failure, labels responsiveness unexercised before readiness, and separates its post-readiness deadline. Cleanup reports whether termination was forced; it does not claim an exit cause from a terminated child. Worker fixture changes were syntax-checked, not rerun on the shared host. New isolated emitter and callback exception/timing-off tests passed (6 tests/21 assertions); the two signaling/app-event gateway tests passed (2 tests/30 assertions) using the existing PR3 dependency tree with PHP8.2.29. No clean-install or full compatibility claim follows. No fresh benchmark or host probe ran. Independent clean-dependency validation, worker readiness evidence and collector review remain pending.

No deployment, merge, live tracing, restart, Apache change or human call is authorized here. Task147, recording acceptance, PR3 independent validation and PR4 clean-dependency/Apache behavioral gaps remain open.

## Collector preparation and residual warning review

`tools/collect-callback-diagnostics.php` is a separately launched collector preparation, never started by gateway code. It binds only literal loopback, creates a new output file without overwriting evidence, and accepts duration1..300 seconds. Nonblocking receives are limited to4096 datagrams and4MiB; datagrams over2048 bytes or outside the fixed validated schema are rejected without printing their contents. Output is additionally capped at4MiB. Fixed final counters report received/accepted/rejected bytes/records and write failure; sender/kernel loss remains unknown. Sender attempt sequence is retained, but absent/reordered sequences are not allocated to kernel loss or confirmed delivery. A filesystem call can stall this independent collector: its time/volume checks do not bound disk syscall latency. No live collector launch or receipt proof is claimed. Loopback is not an authentication boundary; another local process can forge schema-valid metadata. The whitelist is a payload-exclusion check, not a guarantee that client-controlled request IDs never contain sensitive text.

Residual synchronous observer paths were inspected: timing-off callbacks taking at least one second still emit a gateway warning; RealtimeServeCommand's one-second loop probe emits a warning on excess drift. Those paths still reach the configured logger and may themselves stall. Product session/room/error logs also remain synchronous. Detailed timing-on callbacks no longer fall back to those warning writes, but this does not eliminate every gateway disk/logging cost. No safe low-load latency figure exists for remaining paths; their cost must be considered before capture acceptance. Changing product/warning semantics requires separate review, and logging absence does not prove a healthy event loop. No new warning benchmark was run.
